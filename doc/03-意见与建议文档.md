# 意见与建议：功能优先级、取舍与风险

> 面向开发者，基于调研结论给出实施建议。核心原则：**先跑通"逛 → 发 → 联"闭环，再叠加信任与治理体系。**

---

## 一、功能优先级建议

### P0 — 最小可行版本（MVP，4~6 周）
没有这些，产品不成立：

1. **登录体系**：微信一键登录 + 游客浏览模式（游客转登录的引导浮层）。
2. **底部导航四页骨架**：首页 / 动态 / 消息 / 我的。
3. **首页快捷服务 + 搜索**：二手/搭子/活动/竞赛四大入口；搜索历史（含单条删除与清空）。
4. **二手交易核心闭环**：发布（3 步向导）→ 浏览/筛选 → 私信沟通 → 订单状态 → 面交双向确认。
5. **动态发布与信息流**：顶部分页 + 混合卡片流；发布走敏感词过滤。
6. **基础消息通知**：系统通知（交易、报名结果）站内触达。
7. **权限硬控制**：游客仅浏览；普通用户可发交易；办活动/竞赛仅认证用户（服务端校验，不只前端隐藏）。

### P1 — 第一轮迭代（+3~4 周）
决定产品是否"好用"：

1. **学号认证流程**（认证状态占位、审核后台）——权限体系的开关。
2. **收藏 + 浏览历史 + 专业偏好推荐**（冷启动规则见脑图备注）。
3. **找搭子**：标签匹配 + 同校限定 + 匹配度百分比（低成本高感知）。
4. **竞赛/活动截止日期自动提醒**——调研中验证的最高频刚需，务必自动化。
5. **草稿自动保存**（发布类页面统一接入）。
6. **举报入口与后台工单**。

### P2 — 第二轮迭代
锦上添花，但决定留存：

1. **信用分与双向评价**（低于阈值限制发布）。
2. **组织者管理后台**：报名审核、签到、名单导出。
3. **搭子组局管理**（人数上限、AA 账单、活动群聊）。
4. **担保交易/资金托管**（需支付资质，见风险）。
5. 深色模式、桌面小组件、分享卡片优化。

### P3 — 暂缓/观察
1. 私密聊天音视频、直播。
2. 会员付费体系。
3. 校际互通、跨校推荐。
4. AI 智能定价/智能摘要（等有数据积累后再做）。

## 二、功能取舍建议

| 功能 | 建议 | 理由 |
|---|---|---|
| 混合信息流（6 种卡片） | **保留但简化首版** | 先做动态/商品/活动竞赛三类卡片，"个人卡"和"校园卡"P1 再上 |
| 担保交易/资金托管 | **首版不做，先做面交双向确认** | 支付资质门槛高；校园场景 80% 以上为面交，双向确认已解决主要纠纷 |
| 即时通讯自研 | **不建议自研** | 直接用微信小程序客服消息或腾讯云 IM SDK（调研案例普遍如此） |
| 内容先审后发 | **发布高峰期开启，平时机审为主** | 全量人审拖慢发布体验；建议机审拦截 + 疑似违规抽样人审 |
| 求购反向推送 | **P1 做** | 实现简单（关键词匹配历史商品），是调研中口碑最好的功能之一 |
| 女性专属搭子模式 | **建议保留** | 低成本、差异化强、对安全口碑价值大 |
| 第二课堂成绩单式成长档案 | **远期观察** | 依赖校方合作，独立产品难落地；可先做简单"参与记录"页 |

**整体取舍哲学**：校园产品的天花板是信任，不是功能数量。宁可砍功能，不可砍治理（举报、审核、封禁必须在第一版就有）。

## 三、风险与应对

### 1. 合规与审核风险（最高优先级）
- **资质**：教育移动应用需备案（参考"到梦空间"的教 APP 备案）；涉及交易需处理平台责任边界；微信小程序类目审核严格。
- **内容风险**：校园动态是 UGC 重灾区（广告、代写、租房违规、涉政涉黄）。**应对**：敏感词库 + 图片审核接口（如微信内容安全 API）+ 举报 24h 处理 SLA + 违规处罚分级公示。
- **交易风险**：私下交易纠纷、诈骗。**应对**：面交双向确认 + 信用分 + 举报仲裁；首版明确"平台仅提供信息撮合"的用户协议。

### 2. 冷启动风险（最高失败率）
- 无人发布 → 无内容 → 无人使用。**应对**：
  - 选 1 所学校试点（调研案例全部是单校起步）；
  - 运营团队自己铺 200~500 条种子内容（二手商品、竞赛信息、活动）；
  - 竞赛信息聚合是最佳冷启动抓手——信息有官方来源、不需要 UGC、刚需高频。

### 3. 技术风险
- **权限绕过**：办活动/竞赛的权限必须服务端双重校验，前端隐藏入口不够。
- **推荐数据不足**：新平台行为数据稀疏，首版推荐权重应为 `专业匹配 40% + 热度 40% + 新鲜度 20%`，不要一开始上复杂算法。
- **消息触达**：小程序模板消息有频次限制，关键通知（截止提醒）要设计重试与多通道（服务通知 + 短信兜底，可选）。

### 4. 运营风险
- **季节性波动**：开学季/毕业季流量峰值与假期低谷。**应对**：提前做"毕业清仓""新生好物"专题（借鉴校淘四大板块）。
- **多角色协调**：认证用户办活动后弃管，参与学生体验受损。**应对**：组织者需缴纳少量信用押金分或通过审核制准入，活动开始前 24h 未响应自动降权。

## 四、给开发者的三条总结

1. **顺序比全面重要**：登录 → 交易闭环 → 信息流 → 通知 → 认证权限 → 推荐 → 治理完善。每一步都让上一步的体验成立。
2. **借鉴要抄机制，不要抄功能清单**：面交双向确认、截止提醒、专业冷启动推荐这三个机制，是本次调研中投入产出比最高的三个"抄作业"点。
3. **把治理当功能做**：举报按钮、审核队列、封禁管理不是后台杂活，是校园产品能否活下去的 P0 能力。
