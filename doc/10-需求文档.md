## 1. 引言

### 1.1 目的与范围

本文档定义「通航校园APP」v1.0 的功能需求、非功能需求与用户场景，是概要设计、数据库设计、API 设计、开发计划与测试用例的唯一需求来源。需求范围覆盖《04-思维导图（重构版）》全部结构，按《03-意见与建议文档》的优先级策略分批交付。

### 1.2 术语与约定

| 术语 | 定义 |
|---|---|
| 游客 | 未登录用户，仅可浏览公开内容 |
| 普通用户 | 已登录（微信/手机号）但未通过学号认证的用户 |
| 认证用户 | 学号认证通过的用户，可发布活动/竞赛、组队 |

## 2. 项目背景与产品目标

### 2.1 背景

校园信息（二手交易、找搭子、活动、竞赛）散落在 QQ 群、微信群与贴吧，碎片化严重：交易无信任、组队靠刷屏、竞赛截止节点靠学生自己盯。调研（见《01-调研总结文档》）验证：**信息聚合与关键节点提醒是刚需中的刚需**。

### 2.2 产品目标

1. **信息聚合**：四类校园信息集中化、结构化，支持分类筛选与搜索。
2. **业务闭环**：形成"逛 → 发 → 联"主链路——交易（发布→浏览→私信→订单→面交确认）、组队（发布→申请→审批→协作）、报名（浏览→报名→提醒→记录）各自走通。
3. **信任与治理**：三级权限 + 内容审核 + 举报仲裁 + 信用分，构成校园信任底座。
4. **个人资产沉淀**：参与记录、获奖与作品形成可展示的成长档案。
5. **单校试点起步**：首版仅面向一所试点高校，以竞赛信息聚合为冷启动抓手。

### 2.3 v1.0 明确不做（负需求）

| 不做项 | 理由（《03-意见与建议文档》） |
|---|---|
| 担保交易 / 资金托管 / 任何资金代收 | 支付资质门槛高；校园场景 80%+ 为面交，双向确认已覆盖主要纠纷 |
| 即时通讯自研 | 接入腾讯云 IM，不自研 |
| 第二课堂成绩单式官方成长档案 | 依赖校方合作，v1 只做个人参与记录页 |
| 校际互通、跨校推荐 | 单校试点期不开放 |
| AI 智能定价 / 智能摘要 | 数据积累不足 |
| 会员付费、直播、音视频通话 | P3 观察项 |

## 3. 用户角色与场景

### 3.1 角色能力矩阵

| 能力 | 游客 | 普通用户 | 认证用户 | 管理员 |
|---|:---:|:---:|:---:|:---:|
| 浏览信息流/搜索/详情 | ✅ | ✅ | ✅ | ✅ |
| 发布动态 / 二手 / 搭子帖 | ❌ | ✅ | ✅ | — |
| 收藏 / 点赞 / 评论 / 私信 | ❌ | ✅ | ✅ | — |
| 报名活动 / 竞赛、申请组队 | ❌ | ✅ | ✅ | — |
| 发布活动 / 竞赛并管理 | ❌ | ❌ | ✅ | — |
| 发布内容加权曝光 | ❌ | ❌ | ✅ | — |
| 内容审核 / 举报处理 / 封禁 | ❌ | ❌ | ❌ | ✅ |

> 权限判定必须**服务端双重校验**（见《11-系统概要设计》§5），前端隐藏入口只是体验层优化。

### 3.2 核心用户场景（User Story）

**US-01 二手交易全流程（普通用户）**
> 小航在首页"二手服务区"刷到一辆九成新自行车，收藏后私信卖家约定明天中午在图书馆门口面交。见面付款后，双方各自在 App 内点击"确认面交"，订单完成，互相评价。若只有一方确认，订单保持"待确认"，不产生纠纷定论。

**US-02 发布闲置（普通用户）**
> 毕业季，小航通过 3 步向导（选图→填信息→预览）发布闲置教材，中途退出，草稿自动保存；再次进入从草稿继续。发布时正文命中敏感词被机器拦截，提示修改后成功发布，进入审核通过后上架。

**US-03 竞赛报名与提醒（普通用户）**
> 小航在"竞赛服务区"按日历看到"互联网+"报名截止还有 3 天，报名后收到系统消息"报名成功"；截止前一天收到模板消息提醒材料提交；初赛结果在消息中心"系统通知"中可见。

**US-03a 组队参赛（普通用户 → 队长）**
> 小航发布"找队友"组队需求（缺 1 名后端），在消息页"申请中心"收到 3 份申请（含技能/简介/理由），同意其中 1 人；新成员入队触发"队伍通知"，全队进入"队伍群聊"讨论分工。

**US-04 找搭子（普通用户）**
> 小航在"搭子服务区"筛选"运动"标签，找到同校羽毛球搭子帖，查看对方性别/爱好/性格后申请加入；对方同意后解锁联系方式进入私聊。

**US-05 办活动（认证用户）**
> 社团负责人小杨（已通过学号认证）发布"迎新晚会"活动，设置报名起止时间、地点、人数上限、报名需审核；在"我的管理"中审核报名申请，活动当天扫码签到，结束后导出名单。

**US-06 游客转登录（游客）**
> 游客浏览首页动态，点击"收藏"时触发登录引导浮层，微信一键授权后权限自动升级，回到原页面继续操作。

**US-07 内容治理（任意用户）**
> 小航刷到疑似诈骗帖，点击卡片"举报"，选择"诈骗"并提交截图；24 小时内收到举报处理结果通知，违规内容下架、发布者被禁言。

**US-08 逛首页（任意用户）**
> 小航打开 App，首页顶部搜索框可搜动态/帖子/重要消息/校园话题（含搜索历史）；下方快捷服务四宫格直达四大业务；再往下是"重要消息"待办区（7 天内截止、报名开始、规则更新）与个性化推荐流（首登按专业，之后按浏览/收藏行为修正）。

### 3.3 边界场景（驱动测试与设计约束）

| 编号 | 场景 | 期望 |
|---|---|---|
| BS-01 | 游客对任意写操作发起请求 | 服务端拒绝并返回 40001，前端弹登录引导 |
| BS-02 | 普通用户调用"发布活动"接口 | 服务端拒绝返回 40003，提示需学号认证 |
| BS-03 | 订单只有单方确认面交 | 订单停留"待确认"，另一方 24h 未响应可申请取消 |
| BS-04 | 重复报名同一竞赛 | 拦截返回 40006，提示已报名 |
| BS-05 | 报名截止后提交报名 | 拒绝返回 40007，提示已截止 |
| BS-06 | 发布内容命中一级敏感词 | 直接拦截（40008）；二级词进入人工复审队列 |
| BS-07 | 待付款/待确认订单超时 | 30 分钟未付款自动取消、面交确认超 72h 自动关闭 |
| BS-08 | 组织者弃管活动 | 活动开始前 24h 未响应自动降权并通知报名者 |
| BS-09 | 被屏蔽用户访问对方内容 | 双向不可见：内容不出现、不可私信、不可申请 |
