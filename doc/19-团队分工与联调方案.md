## 1. 团队组织

### 1.1 规模推定结论

由《14》§5：S1（MVP，6 周）峰值前后端并行任务线 = 前端 3 条 + 后端 4 条，且总工时（前端 ≈150pd / 后端 ≈220pd）按 5pd/人周有效产出折算，最小不阻塞配置为 **10 人**。规模再小则 S1 关键路径（上传审核→发布类功能→联调）必然超期；更大则 S0/S2/S3 出现空转。

### 1.2 组织结构（10 人，代号 A~J）

```
项目经理 J ──────────────── 兼产品负责人 / 合规接口人
│
├── 前端组（组长 A）      A · B · C          ── 微信小程序
├── 后端组（组长 D）      D · E · F · G      ── campus-server
├── 设计 H                                  ── UI/UX（虚线支持全员）
└── 测试 I                                  ── 质量守门（《15》）
```

## 3. 联调范围

| 联调面 | 内容 | 参与方 |
|---|---|---|
| **F1 前后端接口联调** | 《13》全部 v1 接口（按里程碑分批，见 §4.2） | 前端 A/B/C × 后端各接口 owner |

| **F3 第三方联调** | 微信登录/模板消息/内容安全 API；TIM（userSig/群聊/卡片）；COS 上传审核 | D（微信）、F（TIM）、全员（上传） |

## 4. 联调约定与节奏

### 4.1 接口契约约定

1. **契约优先**：Apifox 为唯一契约源（结构来自《13》），开发前 3 天接口 owner 必须发布 Mock；前端只面向 Mock 开发，不等待后端；
2. **变更三步**：Apifox 改 → 评审（BE-D + 受影响前端）→ 通知群公告；破坏性变更升 v2（§13.5）；
3. **字段规约**：camelCase / ISO8601+08:00 / 分页与错误码全遵守《13》§1~2，任何人不得私设错误码；
4. **联调数据**：test 环境种子数据由 I 维护（每日重置），包含四类角色账号（游客/普通/认证/管理员）与边界数据（大图、敏感词样本、临截止竞赛）。

### 4.2 时间节点（对齐《14》里程碑）

| 窗口 | 时间 | 内容 |
|---|---|---|
| 每周五 | W2 起，半天 | F1 当周接口联调日（Apifox Mock → 真实接口切换） |
| 集中联调周 ① | W7（M1 前） | P0 全接口 F1/F2/F3 + F5 冒烟 → α 版 |
| 集中联调周 ② | W11（M2 前） | P1 接口 + 提醒任务实测（真机收模板消息）→ β 版 |
| 集中联调周 ③ | W15（M3 前） | P2 接口 + 性能预压 → RC 版 |
| 发布演练 | W16 | 生产部署 + 回滚演练（《16》§8）+ 全量回归 |

### 4.3 环境准备（owner：D，W1 完成）

| 环境 | 地址约定 | 用途 |
|---|---|---|
| dev | `http://dev.campus.local:8080/api/v1` | 自测，数据可随时重置 |
| test | `https://test-api.campus.example.cn/api/v1` | 联调/测试，每日 0 点重置，小程序体验版指向此环境 |
| prod | `https://api.campus.example.cn/api/v1` | W16 起启用，域名白名单见《16》§4 |

**联调前置检查**（每周四发出）：CI 绿 ｜ Mock 全量 ｜ 种子数据就位 ｜ TIM 测试套件可用 ｜ 体验版二维码已更新。

### 4.4 问题反馈机制（联调问题单）

**渠道**：企业微信「通航-联调」群（即时）+ 禅道缺陷单（留痕）；群内只报不修，落单才修。

**问题单必填字段**：
`任务号/接口名 · 环境 · 复现步骤 · 期望 vs 实际 · 抓包/截图 · traceId`

**分级响应**（与《15》§4 一致）：

| 级别 | 定义 | 响应 | 修复 |
|---|---|---|---|
| S1 | 主链路不可用 / 越权 / 数据错乱 | 30 分钟内认领 | 当日修复 + 回归 |
| S2 | 功能不可用但有绕行 | 2h | 48h |
| S3 | 体验缺陷 / 文案 | 当日认领 | 本里程碑内 |
| S4 | 优化建议 | 周会批量 | 排期协商 |

**升级路径**：24h 未认领 → 组长（A/D）介入 → 48h 未解 → J 仲裁（裁范围或裁排期），裁决记入《14》变更记录。

**复盘**：每个集中联调周结束次日，J 主持 1h 复盘：TOP3 问题类型、契约缺口、下阶段预防项（落入本表与《18》登记册）。
